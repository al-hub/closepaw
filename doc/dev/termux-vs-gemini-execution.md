# Termux와 Gemini 실행 방식의 차이

작성일: 2026-10-17 (KST)
기준: ClosePaw v0.1.48. 이후 구현이 바뀌면 현재 기능과 목표를 구분하여 갱신한다.

## 핵심 설명

두 경로 모두 ChatGPT → ClosePaw → 실행 결과 반환이라는 흐름을 사용하지만, 휴대폰에서 실행하는 방식이 다르다. 명령 전달이 가능하다는 사실이 모든 앱의 백그라운드 제어를 의미하지는 않는다.

| 항목 | Termux 셸 실행 | 현재 Gemini 앱 제어 |
| --- | --- | --- |
| 실행 경로 | 로컬 브리지에 셸 명령을 전달하여 실행 | Gemini를 열고 접근성으로 대상 화면·입력창을 식별하여 조작 |
| 화면 사용 | 일반 명령 실행은 Termux 화면을 앞에 띄울 필요가 없음 | 조작·읽기 시 식별 가능한 Gemini 화면이 전면에 있어야 함 |
| 결과 확보 | stdout, stderr, 종료 코드, 시간 초과·출력 잘림 등의 실행 결과 | 현재 보이는 접근성 텍스트, 필요 시 화면 OCR 및 제한된 캡처 |
| 성공 판단 | 요청 작업의 출력과 종료 상태를 함께 판단 | 요청 동작 후 실제 화면 상태를 확인해야 함 |
| 주요 제약 | 브리지 준비 상태, 프로세스 유지, Android 백그라운드 실행 제한 등 | 잠금, 권한, 다른 앱으로 전환, 화면 구조·대상 변경 등 |
| 답변 범위 | 명령이 반환한 출력 범위 | 확보한 가시 화면 범위이며 전체 대화 수집을 보장하지 않음 |

Termux도 항상 실행 가능하다는 뜻은 아니다. 최초 설정이나 장애 복구에는 사용자 조작이 필요할 수 있다. 셸 경로를 Android UI 조작이나 앱별 제한 우회에 사용하지 않는다.

## v0.1.48에서의 Gemini 기능 경계

- 앱 실행 및 현재 화면 읽기.
- 빈 Gemini 입력창에 초안을 입력하고 입력 결과를 확인.
- 기존 초안 덮어쓰기 차단.
- 등록된 초안 입력 작업은 전송 버튼을 누르지 않는다. 질문 자동 전송과 답변 완료 대기는 현재 기능으로 간주하지 않는다.
- Google 앱 패키지라는 이유만으로 Gemini로 인정하지 않는다. Gemini 전용 입력창 등 기존 식별 조건으로 대상 화면을 확인한다.

## 다음 Gemini 왕복 개발의 의미

계획된 흐름은 질문 입력 → 전송 → 새 답변 완료 확인 → 답변 수집 → 같은 Voice 대화에서 설명이다. 전송과 대기를 자동화해도 화면 기반 제어가 자동으로 백그라운드 API 실행으로 바뀌지는 않는다. 구현·배포·실기기 검증이 끝나기 전에는 완성으로 보고하지 않는다.

진정한 비화면 실행에는 해당 기능을 제공하는 별도의 공식 API나 서비스 연동 경로가 필요하다. 이 문서는 그런 연동의 제공 여부 또는 Gemini 앱과 동일한 계정·대화·위치 기능을 보장하지 않는다.

위치처럼 권한에 의존하는 기능은 질문·답변 왕복 성공과 위치 확인의 정확도를 별도로 판단한다. 필요한 권한이 없으면 사용자에게 필요한 조작을 안내하고, 추정 지역을 정밀 위치로 설명하지 않는다.

## 다시 질문할 때의 짧은 답

“Termux는 브리지로 명령을 실행하고 출력과 종료 상태를 받습니다. 현재 Gemini는 전면 화면을 조작하고 표시된 답변을 읽습니다. 전송 자동화 후에도 이 차이는 유지됩니다.”
