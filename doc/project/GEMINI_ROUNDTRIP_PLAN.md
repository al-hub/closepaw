# Gemini 목표 실행·확인·후속 조치 전체 동작 계획

작성: 2026-10-17 KST. **서브 에이전트 3개로 구현·통합하고 v0.1.49 서명 APK를 발행했다. 실기기 왕복 인수는 아직 대기 중이다.**
배포 시간 최적화는 이번 범위에서 보류한다.

## 목표와 현재 기준

사용자가 ChatGPT Voice에서 Gemini에 대한 목표를 지시하면, ChatGPT가 필요한
동작을 정하고 ClosePaw가 실행한다. 반환된 실제 상태를 확인하여 허용된 후속
동작을 수행하고, 목표 달성 또는 구체적인 중단 사유를 같은 Voice 대화로 설명한다.
질문·응답 왕복을 핵심 인수 시나리오로 삼되 한 번의 명령 전송만으로 완료하지 않는다.
사용자가 Termux·SSH·내부 어댑터를 조작할 필요가 없어야 한다.

대표 요청: “초안만 작성해”, “질문을 보내고 답을 알려줘”, “현재 답변을 읽어줘”,
“그 답변에 대해 추가로 물어보고 결과를 확인해줘”. 추가 질문은 사용자 요청 범위
안에서 수행한다. 새 대화·현재 대화의 선택은 UI 지원과 의도를 확인하여 계약에
포함한다. 이 구조는 Gemini에서 검증한 뒤 같은 operation registry로 다른 앱에 확장한다.

- 현재 배포 작업: v0.1.48/code49, PR #93 병합 완료. 읽기의 Google-host 판정
  불일치 수정이며 설치 후 실제 READ/Voice 검증은 아직 남았다.
- 기존 `gemini.draft.insert`는 빈 입력창에 초안을 넣는 기능이다. 전송하지 않는다.
  이번 기기의 입력 성공 인수는 아직 없다.
- 질문 전송, 이번 질문에 대응하는 답변 판별, 생성 완료 확인과 답변 수집은
  추가 구현 대상이다. 준비 상태/CI 성공을 실기기 성공으로 간주하지 않는다.
- 기존 MCP operation envelope와 페어링/터널 설정을 유지한다. 플러그인 재등록을
  전제로 설계하지 않는다. 다음 버전 번호는 개발 착수 시 최신 상태에서 정한다.

## 개발 방식

다음 개발 단위는 질문·응답 왕복 전체를 포함하는 하나의 통합 범위로 잡는다.
각 내부 기능은 SRP에 따라 나누고 TDD로 검증하되, 사용자의 단계별 수동 조작을
전제로 작은 기능만 계속 배포하는 흐름을 줄인다. 통합된 기본 시나리오를 실제
기기에서 끝까지 검증한 다음 실사용 결함 수정과 신뢰성 범위를 넓힌다.

## 구현 범위

| 단계 | 동작 | 필수 판정 |
| --- | --- | --- |
| 요청 접수 | 질문·대상·작업 ID 접수 | 질문 전송을 요청한 의도와 초안 입력 요청을 구분 |
| 준비 | Gemini 실행, 잠금/권한/전경 및 호스트 UI 확인 | 일반 Google Search 거부; 사용 가능한 실행 채널 안에서 먼저 직접 처리 |
| 입력 | 기존 guarded composer를 재사용하여 질문 입력 | 빈 입력창, 유일한 대상, 입력 문자열 일치; 기존 초안 보존 |
| 전송 | Gemini의 식별된 전송 컨트롤로 한 번 제출 | 동일 요청 ID 중복 제출 금지; 좌표 추측/Enter 키 우회 없이 의미 기반 동작 |
| 생성 대기 | 비동기 작업으로 상태 관측 | 제출 증거와 이번 응답의 새 생성 상태를 구분; 제한 시간 적용 |
| 답변 수집 | 이번 질문 이후 새 답변 텍스트 수집 | 기존 답변/모델 메뉴/질문 재인용을 새 답변으로 오인하지 않음 |
| 반환 | 확인된 답변과 완료·부분·불확실 상태 반환 | ChatGPT가 같은 Voice 대화에서 근거 있는 결과 설명 |

기본 인수는 한 번의 질문 왕복이며, 현재 답변 읽기·초안만 작성·명시된 추가 질문도
전체 제어 흐름에서 분기한다. 현재/새 대화 선택을 지원할 때는 대상 대화를 확인하고,
식별이 모호하면 임의로 선택하지 않는다. 기록 전체 탐색·모델 선택·첨부·Gemini Live는
이번 목표의 필수 동작과 분리한다. “전체 동작”은 목표 실행·관측·후속 조치·완료 보고의
연결을 뜻하며 Gemini의 모든 UI 기능을 무제한 제어한다는 주장이 아니다.

## 구조와 계약

- `GeminiUiInspector`: native/Google-host 전경과 입력창·전송 버튼·생성 상태·
  답변 영역의 관측을 담당한다. 기존 검증을 재사용하고 읽기/쓰기 판정의 중복을 줄인다.
- `GeminiQuestionSubmitter`: 입력 검증과 단 한 번의 전송 및 제출 증거를 담당한다.
- `GeminiReplyCollector`: 제출 기준점 이후의 새 답변과 완료·부분 수집을 담당한다.
- `GeminiRoundTripOperation`: 위 요소를 조합하고 시간 제한·작업 상태·복구를 관리한다.
  기존 `execute`/`get_task`/`discover_operations`와 작업 저장소를 재사용한다.
- ChatGPT는 반환된 상태를 근거로 사용자 목표 달성을 판단한다. 후속 동작은 허용된
  operation과 사용자 요청 범위에서 횟수·전체 시간을 제한해 수행한다. 미지원 동작은
  바로 설명하고, 인증·잠금 등 실제 필요한 사용자 조작만 구체적으로 요청한다.
- 새 operation ID는 예를 들어 `gemini.question.ask`로 두되 착수 시 계약을 확정한다.
  기존 draft operation의 “절대 전송하지 않음” 계약은 유지한다.
- 전송 권한은 기존 초안 입력 권한과 구분한다. 설정은 최초 허용 범위에서 관리하고,
  사용자가 명확히 요청한 일반 질문마다 불필요한 재확인을 반복하지 않는다.
- 작업은 비동기로 실행하고 같은 작업 ID를 조회한다. 기다리는 동안 UI 스레드나
  MCP 요청을 장시간 점유하지 않는다. 전송 중/결과 불확실 상태를 영속화한다.

## 처음부터 포함할 보호와 실패 처리

1. **전송 상태:** `not_sent → submitting → sent → waiting → completed`를 구분하고
   `outcome_unknown`을 별도로 둔다. 전송 직후 프로세스가 종료되어 확인이 끊기면
   자동 재전송하지 않는다. task ID·제출 증거로 재관측하거나 불확실 상태를 반환한다.
2. **입력 보호:** 기존 초안, 잠금, 권한 OFF, 모호한 입력창, 대상 전환이면 쓰기를
   중단한다. 전송 직전 권한·전경·입력 일치를 다시 확인한다.
3. **응답 판별:** 전송 전 기준점을 잡고 이번 질문 이후 새 응답임을 확인한다.
   생성 표시 종료와 응답 영역의 안정성을 함께 보며, 텍스트가 잠시 멈춘 것만으로
   완료를 단정하지 않는다. UI 버전이 미지원이면 제한을 명시한다.
4. **긴 답변:** 답변 영역을 제한적으로 수집한다. 필요 시 같은 응답 범위에서만
   횟수·시간·분량을 제한한 스크롤과 중복 제거를 적용한다. 끝을 확인하지 못하면
   부분 답변으로 표시한다. 외부 검색이나 다른 대화의 내용으로 채우지 않는다.
5. **중단·실패:** 전송 전 취소와 전송 후 대기 중단을 구분한다. 실제 생성 취소를
   확인하지 못하면 Gemini 생성이 멈췄다고 말하지 않는다. 시간 초과는 같은 작업의
   조회/부분 결과로 처리하며 질문을 자동 재전송하지 않는다.
6. **진단:** 단계·작업 ID·패키지/윈도우·오류 코드·시간을 제한적으로 기록한다.
   질문/답변 원문·토큰·스크린샷을 진단 로그에 영속화하지 않는다.

## 대표 실기기 인수 — Gemini를 통해 현재 위치 알려줘

사용자가 선택한 대표 문구: **“Gemini를 통해 현재 위치 알려줘.”**
질문 전송은 명시적 사용자 요청과 로컬 질문 전송 권한이 있을 때만 수행한다. 실기기 인수 전에는 위치 질문을 시험 전송하지 않는다.

1. 기존 연결을 유지하고 실제 설치 버전과 필요한 로컬 실행 권한을 확인한다.
   질문·전송·응답 수집 기능 구현과 서명 APK 설치가 완료된 뒤 수행한다.
2. 같은 ChatGPT Voice 대화에서 위 문구로 요청한다. Gemini를 실행하고 입력창·
   대상 대화를 확인하여 질문을 한 번 전송한다. 기존 초안이 있으면 보존하고 중단한다.
3. 이번 질문에 대한 새 답변과 생성 상태를 관측한다. 이전 답변, 모델 메뉴,
   질문 문구 자체를 위치 결과로 오인하지 않는다. 제한 시간 내 확인되지 않으면
   같은 task를 조회하고, 질문을 자동 재전송하지 않는다.
4. Gemini가 반환한 위치 표현과 정확도/근거/권한 부족 안내를 수집한다.
   ChatGPT는 그것이 Gemini의 반환 결과임을 분명히 하고 실제 위치·추정 지역·
   확인 불가를 구분해 같은 Voice 대화로 설명한다. 추정을 정밀 GPS로 바꾸지 않는다.
5. 물리적 현재 위치와의 일치 여부는 사용자가 알고 있는 장소 또는 별도로 허용된
   위치 근거와 대조할 수 있을 때만 검증한다. 그 근거 없이 정확성을 인증하지 않는다.
   Gemini의 위치 권한 변경/시스템 동의가 필요하면 실제 요청과 이유를 설명한다.
6. 최종 증거는 작업 ID·단계·시간·결과 분류와 사용자 인수 여부로 남긴다.
   정확한 좌표·주소·위치 답변 원문은 공개 GitHub 문서/진단 로그에 기록하지 않는다.

| 평가 축 | 통과/실패 기준 |
| --- | --- |
| 제어 왕복 | 질문 한 번 제출 → 이번 답변 수집 → 정확한 상태의 같은 Voice 결과 설명. Gemini가 위치를 모른다는 답변도 제대로 수집하면 왕복 자체는 통과 가능 |
| 위치 확인 | 실제 위치를 확인할 권한/기능/근거가 있고 대조 결과가 일치할 때 성공. 추정·권한 부족·미지원·미확인은 각각 별도 결과 |

이 예시가 위치 기능 문제로 막혔을 때는 위치가 필요 없는 짧은 일반 질문으로
왕복 결함 여부를 분리 진단한다. 그 대체 시험을 위치 확인 성공으로 표시하지 않는다.

## 완료의 정의

실제 Galaxy에서 대표 요청 “Gemini를 통해 현재 위치 알려줘”로
앱 실행·질문 입력·한 번 전송·새 답변 수집·같은 Voice 대화의 결과 설명이
성공하고, 필수 보호 검증의 증거가 기록되어야 왕복 완료로 표시한다.
P2의 READ/Voice 완료와 왕복 operation 완료는 각각 증거를 남긴다.
CI·APK 발행·설치·실기기 왕복 성공을 서로 구분한다.
